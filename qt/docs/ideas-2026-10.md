# Ideas: what other apps have, and what only this app can do (2026-10-04)

A comparison with GoodNotes 6, Notability, Drawboard PDF, Xodo, PDF Expert, OneNote, Samsung Notes, Nebo,
Obsidian (with Excalidraw and Canvas), Zotero's reader, reMarkable, Apple Notes and Preview, and Okular, made on
2026-10-04 against what the app had then (ROADMAP, TODO). Items the author chose to build are marked **(chosen)**
and have blocks in [TODO.md](../../TODO.md); the others are kept here to decide later. Sizes: S about 1–2 days, M
about 3–5 days, L more.

## B) What only this app can do (in the spirit of Markdown inside a PDF with notes)

| # | Idea | Why it fits this app | Size | Risk |
| --- | --- | --- | --- | --- |
| B1 | **A PDF that explains itself**: every PDF with notes carries a `notes.md` attachment, rewritten on save: typed text, the best handwriting readings, annotations and links per page with `#page=` anchors | any indexer, LLM or tool that reads PDF attachments gets the notes without the app; the `.md` attachments (`qt/md-pdf`), the annotations export and the handwriting readings exist | M | privacy and size: an option |
| B2 | **The CLI as an agent tool, then MCP over stdio**: `search <library> "query"` (fuzzy syntax, handwriting included), `cat doc.pdf --page 3 --md`, `render --page 3 --dpi 100`, `backlinks`, `append note.md` | the per-folder index is plain files, no server; VISION's "Further out" | M (+2 days MCP) | the index code lives in `xqt-shell`; writes while the app runs go through `SingleInstance` |

## B9) A document timeline (the author, 2026-10-04; 2026-10-05: levels 1 and 2 decided as one design, block `qt/timeline`)

A play bar at the bottom, like an audio player, that replays the recording and how the document was written, read-only.
What the code has today, and three levels of building it:

- **Today:** points carry only x, y and pressure (no time). Strokes and texts carry upstream's `ts`/`fn` (milliseconds
  into a recording) only while audio is being recorded (`qt/audio` stamps them as upstream does). The undo stack lives
  in memory only and holds pointers, so it cannot be saved. Document events are per page (`DocumentListener`:
  page changed, inserted, deleted), not per element. Incremental PDF saves keep a coarse snapshot per save.
- **Level 1: replay with the recording** (Notability's best-known feature). Elements with `ts ≤ t` are shown, in the
  order they were written; each stroke is drawn on progressively (spread evenly over its length, as no point has a
  time). The play bar is the audio's position; tapping a stroke seeks there (planned in `qt/audio`). Needs a render
  filter by time in `PageRaster` (next to `rasterMarkAudioStrokes`) and a timeline pill. Limits: only what was
  written while recording; erasing and moving are not replayed (strokes show where they ended up). Size M, after
  `qt/audio`. Upstream compatible.
- **Level 2: the order of writing without audio.** Every element gets a creation time (`xqt-created`, an attribute
  Xournal++ ignores and drops when it saves, a seam like `xqt-group`), so the bar replays the writing across all
  sessions, with or without a recording. Still no erasing or moving. Size S–M.
- **Level 3: the full history** (erasing, moving, recolouring, page changes). A journal of changes with times, taken
  where undo steps are recorded (the elements added and removed by each step, serialised as upstream does for the
  clipboard), stored in the PDF with notes as an attachment or in the library cache; replay applies it to a read-only
  copy. Size L (2–3 weeks). Risks: erased ink is kept in the file (against the privacy rule that Share compacts
  away old versions), file size grows with every change.
- Decided (2026-10-05): levels 1 and 2 are one engine with one clock (absolute creation times; a recording is a
  track placed by its start time), built together as `qt/timeline`. Level 3 waits for the version history (B6).
- Suggested path (before): Level 1 right after `qt/audio` (small, upstream compatible, the feature people know from
  Notability); Level 2 if replay without audio is wanted; Level 3 only if the full history is worth the privacy
  and size cost (then as an option, kept out of shared files). B6 (versions inside the PDF) is a cheaper, coarse
  relative of Level 3.
